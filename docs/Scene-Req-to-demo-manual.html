1 概览

单一 Skill 覆盖从场景输入到双轨 Demo 交付的完整链路。核心特性：双轨 Demo、子系统自适应布局、安全标记、两段式约束版。

2 工作流 — 7 步

Step 1 — 生成场景 JSON LLM：5 锚点 + safetyRelevance + acceptanceCriteria Step 2 — 校验 + 领域/子系统检测 analyze.py → status / subsystem Step 3 — 批量确认 ⚠️必问 "是否还有场景？" → merged.json Step 4 — 参考页 ⚠️必问 "是否有参考页？" → ref-styles.css（可选） Step 5 — 合并校验 validate-anchors.py（8 项检查） Step 6a — Markdown + 约束版 render-markdown.py + render-demo.py Step 6b — 创意版（仅非安全） LLM 写 tpl → build-creative.py 注入 Vue + 冒烟 Step 7 — 报告输出路径 脚本打印实际路径
⛔
Step 3 / Step 4 是强制提问点（MUST ASK）：未获用户答复前不得跳过或继续。无论单场景还是多场景，都必须问"是否还有场景"和"是否有参考页"。

安全标记（安全系统无前端）

⚠️
关键认知：安全苛求系统（联锁/ATP/ZC/VOBC 等）实际无操作前端界面。故安全场景的 Demo 是阐述图（逐条展示安全功能 + 验收准则），顶部自动注入「安全功能阐述图·实际安全系统无操作前端界面」横幅 + 角标；Markdown 同步注入安全声明。安全场景不生成创意版。

检测优先信任 FR 显式 safetyRelevance 标注；无标注才用强安全关键词兜底（排除 进路/道岔/闭塞/防护 等弱词，避免 ATS/CTC 误判为安全）；v0.0.5 修复的旧 bug 是 ATS 的"进路自动触发"被误判为 safety。

实测对照（同一约束版，按 safety 判断走不同分支）

安全场景（车站联锁）· 顶部"安全功能阐述图"横幅+角标，逐条安全功能卡片（标注安全相关 + 验收准则），不走两段式

GAP 纪律（防编造）

量化指标（响应时间/准确率/可用性等）无标准依据时必须标 [假设] 或 [GAP]，禁止凭空给确定数值。安全系统相关遵循 domain-railway.md 三条铁律。

5 安装 — 单一权威副本 + 软链

支持 Claude Code / OpenCode / WorkBuddy / Amp。核心原则：只维护一份权威副本，其余位置全部软链，避免多副本升级漂移（v0.0.5 修复过的坑）。

⚠️
务必软链、勿用复制：若某处是独立实体副本，升级时会漂移成旧版——而 SKILL.md 的 find helper 会优先命中第一个找到的副本，导致跑到旧脚本、出旧布局。

推荐：git clone（无缝升级）

# 安装（文件夹名稳定为 scene-req-to-demo）
git clone https://github.com/Githantao/scene-req-to-demo.git ~/.agents/skills/scene-req-to-demo

# 其余 agent 位置软链到权威副本
ln -sf ~/.agents/skills/scene-req-to-demo ~/.config/opencode/skills/scene-req-to-demo
ln -sf ~/.agents/skills/scene-req-to-demo ~/.workbuddy/skills/scene-req-to-demo
ln -sf ~/.agents/skills/scene-req-to-demo ~/.claude/skills/scene-req-to-demo

# 升级（原地，不产生新文件夹）
git -C ~/.agents/skills/scene-req-to-demo pull

不用 git：下载 Release 资产

从 Release 页下载 scene-req-to-demo.zip（Assets），解压即稳定的 scene-req-to-demo/ 目录，覆盖旧安装。

⚠️
不要下载 GitHub 自动生成的 "Source code (zip)"——它带 -版本号 后缀，每次升级产生新文件夹，无法无缝覆盖。

11 FAQ

Q: 双轨 Demo 和旧的单一 Demo 有什么区别？

v0.0.5 起 Demo 分双轨：约束版（脚本确定性、两段式、评审用）+ 创意版（LLM 自由、启发用）。旧版是单一脚本 Demo，已废弃。

Q: 为什么约束版是两段式？

因为单个/几个场景的需求往往不足以铺满整个前端页面。两段式上段展示"需求落在系统架构的哪几块"（其余标范围），下段展示"整页做出来的生产级观感"，不硬把需求撑满整页。

Q: 安全场景为什么没有正常 Demo？

安全苛求系统（联锁/ATP 等）实际无操作前端界面，其 Demo 是"阐述图"（阐述安全功能逻辑），带横幅声明，且不生成创意版。

Q: creative.tpl.html 是什么？

创意版的中间模板（LLM 写占位符 → build-creative.py 注入 Vue）。build 成功后自动删除，不会残留在 output。

Q: 升级后布局变旧 / 跑到旧脚本？

多半是某处是独立实体副本（非软链）漂移成旧版。确保除 ~/.agents/skills/ 权威副本外，其余位置都是软链。

Q: Demo 的 file:// 双击空白？

Vue 已内联无需 CDN。若空白，按 F12 查控制台，或 python3 -m http.server 8899 后访问 http://localhost:8899/xxx.html。

Q: 迁移给其他机器/agent 传什么？

传整个 scene-req-to-demo/ 目录，或 git clone。其余位置软链到权威副本。
