> **使用方式**：当 `analyze.py` 的 `domain_info.matched=true` 时，按 `domain_info.subsystem` 选择对应章节前置注入。
> 未命中时不加载，保持通用分析的简洁性。
>
> **知识来源标注**：本文件为 `knowledge_only`（基于公开标准与行业惯例整理，**未经信号专业工程师签署**）。涉及安全认证、具体阈值时，输出必须提示"需专业复核"，禁止当作已确认事实。

## ⚠️ 安全 / 非安全边界三条铁律（最高优先级）

无论场景落在哪个子系统，以下三条必须遵守，违反即视为专业错误：

1. **监测系统只读**：MSS/集中监测对信号设备是**采集不控制**——监测类需求严禁出现"控制/操作/驱动"安全设备的表述。
2. **安全系统无前端**：联锁/ATP/ZC/VOBC 等安全苛求系统运行在专用认证硬件上，**本身没有操作前端界面**。为其生成的前端页面仅是**需求阐述图**，必须由 `render-*.py` 自动注入阐述横幅；实际操作界面由非安全系统（ATS/CTC）承载。
3. **预测/性能指标禁止编造**：预测准确率、响应时间、可用性等量化指标若无标准依据，必须标 `[假设]` 或 `[GAP]`，不得凭空给出确定数值。

# 第一部分 · 安全篇（subsystem = safety）

## 术语表（安全侧）

| 术语 | 英文 | 含义 |
|------|------|------|
| 联锁 | Interlocking | 信号机/道岔/进路之间的安全制约关系 |
| 进路 | Route | 列车在站内运行的径路，由信号机防护 |
| 道岔 | Turnout | 列车转向设备，定位/反位两种状态 |
| 信号机 | Signal | 防护进路的信号设备，开放/关闭两种状态 |
| 轨道电路 | Track Circuit | 检测区段占用/空闲的设备 |
| 计轴 | Axle Counter | 轨道电路之外的占用检测设备 |
| 闭塞 | Block | 保证列车运行安全间隔的技术 |
| 接近锁闭 | Approach Locking | 列车接近时锁闭进路防止取消 |
| 敌对进路 | Conflicting Route | 与已建立进路冲突的其他进路 |
| 故障导向安全 | Fail-Safe | 设备故障时输出安全侧 |
| CBTC | CBTC | 基于通信的列车控制系统（IEEE 1474），ATS/ATO/ATP/ZC/VOBC 架构 |
| 移动闭塞 | Moving Block | 基于前车位置动态计算 MA |
| MA | Movement Authority | 移动授权，含目标距离/允许速度/坡度 |
| ZC | Zone Controller | 区域控制器，轨旁 ATP，计算 MA 和防护包络 |
| VOBC | Vehicle On-Board Controller | 车载控制器，定位+超速防护+自动驾驶 |
| OC | Object Controller | 目标控制器，TACS 轨旁节点驱动道岔/屏蔽门 |
| SIL | Safety Integrity Level | 安全完整性等级，SIL 4 最高（EN 50129 / IEC 62425） |

## 联锁/列控需求分析特殊规则

1. **进路生命周期三阶段**：建立（条件检查→道岔动作→锁闭→信号开放）、保持（接近锁闭+敌对锁闭）、释放（分段解锁/延时解锁）
2. **SIL 4 约束**：安全苛求功能考虑冗余架构（2×2取2/三取二），THR ≤ 10⁻⁹/h（引自 EN 50129 SIL4 目标值，**标注为标准依据**）
3. **接口一致性**：CBI/RBC/TCC/CTC 子系统间接口数据状态一致，通信故障考虑降级处理
4. **降级模式覆盖**：正常+降级（通信中断/轨道故障/道岔失表）+应急（引导进路/紧急关闭）三种场景
5. **时序图选择优先级提升**：多系统条件验证和联锁逻辑检查时，`sequenceDiagram` 优先级排在 `flowchart` 之前

## CBTC/TACS 需求分析特殊规则

1. **CBTC 子系统交互识别**：ATS/ATO/ATP/ZC/VOBC 交互边界，交互密集场景（MA更新/位置报告/门联锁）自动触发 `sequenceDiagram`
2. **移动闭塞关键要素**：MA 计算依赖前车位置+线路数据+安全包络，MA 相关 FR 必须包含"安全防护包络"和"最不利位置偏移"
3. **定位可信度管理**：覆盖定位误差来源（滑行/空转/应答器漏读/轮径磨损）和安全冗余处理
4. **TACS 分布式逻辑**：资源管理 FR 必须包含冲突检测和互斥访问的 TSM 仲裁机制
5. **降级模式全覆盖**：覆盖 3 级以上降级路径——CAM→ATPM→RM→限制人工，列出每种模式的安全防护手段
6. **门安全联锁不可分割**：列车门+屏蔽门联动是单原子 FR，不可分解为开门/关门/发车等多个 FR
7. **SIL 约束追溯**：ZC/VOBC/OC/T2T 标注 SIL 4，DCS 安全应用层标注 SIL 4

## 安全侧 FR 标注要求

- 安全相关 FR 必须 `safetyRelevance: "安全相关"`
- 安全相关 FR 的 `uiLocation` 应指向**逻辑层**（如"联锁逻辑层""ZC 计算模块"），**不得指向具体页面/弹窗**（安全系统无前端）
- `acceptanceCriteria` 必须给出可测试的安全条件（如"敌对进路存在时禁止开放信号"）

# 第二部分 · 非安全篇（subsystem = ats / ctc / monitoring / iom）

## ATS — 列车自动监控（行车指挥）

- **定位**：非安全（SIL 0/2），调度员与系统的操作接口，管理行车、事件/报警、对外接口
- **典型功能**：运行图/时刻表管理、进路自动触发、列车跟踪、运行调整（扣车/跳停/限速）、事件报警
- **FR 模式**：采集列车位置→站场图渲染→运行图绘制→自动排路→报警提示
- **数据流**：ZC/联锁 状态 → ATS 显示；ATS 命令 → 联锁执行（ATS 只下达意图，安全由联锁保证）
- **界面传统**：调度员工作站+大屏，中央=站场图，两侧=运行图+报警窗（详见 `prototype-domain-ui.md`）

## CTC — 调度集中（国铁/城际）

- **定位**：非安全层，行车集中指挥，下接联锁/监测
- **典型功能**：车次号跟踪、实际运行图、进路遥控、调度命令下达、列车记点
- **FR 模式**：车次号输入/跟踪→实际运行图绘制→进路遥控命令→调度命令管理
- **界面传统**：运行图（时距图）为核心，调度命令窗独立（详见 `prototype-domain-ui.md`）

## MSS / CSM — 维护支持 / 信号集中监测

- **定位**：非安全，**只读**监测信号设备模拟量/开关量（铁律 1）
- **典型功能**：转辙机动作电流曲线、轨道电路电压、信号机灯丝电流、电缆绝缘、报警分级、波形回放、报表
- **FR 模式**：模拟量采集→阈值比对→分级报警→曲线/波形展示→历史回放
- **界面传统**：左设备树+右曲线图+底报警条（详见 `prototype-domain-ui.md`）
- **注意**：报警/曲线类需求严禁出现控制表述

## IOM — 智能运维 / 综合运维管理

- **定位**：非安全，设备全生命周期运维管理，信息化/云平台属性最强
- **典型功能**：设备台账、健康管理（PHM）、故障预测、维修工单、检修计划、备件库存、登销记卡控
- **FR 模式**：台账管理→健康评价→故障预测→工单流转→计划/备件协同
- **界面传统**：仪表盘网格/看板/工单列表，现代大屏风格（详见 `prototype-domain-ui.md`）
- **注意**：故障预测准确率等指标必须标 `[假设]`（铁律 3）；云平台/信创需求标注技术约束

## 运营监测/健康管理通用规则（适用于 monitoring / iom）

1. **三类故障分级**：运营故障（红）/ 运营风险（橙）/ 设备异常（黄）— 对应不同响应等级和处置流程
2. **故障生命周期**：今日故障 → 遗留故障 → 未关闭故障，每阶段有不同的跟踪和关闭条件
3. **健康评价维度**：频发异常 / 纳入跟踪 / 切机事件 / 分路不良处所 / 检验监督
4. **大屏看板要素**：线路全景、实时告警计数、趋势图、库存预警、人员动态
5. **施工/检修卡控**：重点施工（重要/配合）、检修卡控（在控/待检）、库存预警（TOP3 缺件）

## FR 撰写通用领域注意事项

- 涉及"进路办理"的需求，必须说明联锁检查条件和降级处理
- 涉及"报警/故障"的需求，必须区分故障等级（Ⅰ类/Ⅱ类 或 运营故障/风险/异常）
- 涉及"配置"的需求，必须说明是项目级可配置还是全局固定
- 涉及"数据同步"的需求，必须说明子系统间的一致性保障
- 每条 FR 的 `dataSource` 应具体到"根据XX code/XX 信号/XX 报文"而非泛泛的"根据系统数据"
- 每条 FR 根据所属子系统标注 `safetyRelevance`，安全侧遵守第一部分标注要求
